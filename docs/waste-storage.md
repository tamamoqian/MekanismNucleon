# 放射性废料存储罐（Nucleon 版）

用 **耐辐射废料存储外壳** 和 **耐辐射废料存储端口** 搭起来的多方块储罐：
只收放射性物品，内部把「待衰变废料」和「衰变完成产物」分成两块空间，
五条衰变配方共用「并行线程池」运行，进度、存量、线程占用全部显示在 GUI 里。

## 1. 方块

| 方块 | 作用 |
|---|---|
| `meknuc:radiation_resistant_waste_storage_casing` 耐辐射废料存储外壳 | 罐体外壳（主方块也在这里） |
| `meknuc:radiation_resistant_waste_storage_port` 耐辐射废料存储端口 | 功能端口，配置工具潜行右键切换模式 |

外壳和端口可以放在罐体外表面的任意一格（包括棱边和角落），内部必须是空气。

## 2. 尺寸与容量

- **底部最大 3 × 3，高度最高 18 格**，最小 1 × 1 × 1。
- 容量按**包围盒体积**计算（体积 = 长 × 宽 × 高，即 `getVolume()`）：
  - 废料物品存储空间：`体积 × 16` 个物品；
  - 衰变完成产物缓存：`体积 × 16` 个物品。
- 例：3 × 3 × 18 = 162 体积 → 各 2592 个物品。
- **并行线程数 = 包围盒体积**：162 体积的储罐同时最多 162 个衰变线程，1 体积的储罐只有 1 个线程。
- 存储按「物品个数」计算，格子只是载体：每格最多 64 个（燃料棒原版只堆 16，
  罐内同样一格 64 根），总上限由体积决定。

## 3. 衰变配方与并行线程

每个线程一次处理 1 个输入，到时间后产出 1 个产物；五条配方共用同一个线程池，
线程数 = 多方块体积。

| 输入 | 产物 | 时间 |
|---|---|---|
| 1 镅-241 粉 | 1 钌粉 | 600 s |
| 1 钚-239 粉 | 1 铀-235 粉 | 300 s |
| 1 铀-235 粉 | 1 铅粉 | 800 s |
| 1 铀-233 粉 | 1 钍粉 | 600 s |
| 1 钋-210 粉 | 1 铅粉 | 100 s |

- 铀-235 粉既是钚-239 的产物，也是「铀-235 → 铅」的输入：
  只有**废料空间**里的铀-235 会被继续衰变，进入产物缓存的铀-235 不会被再消耗。
- 线程启动时就从废料空间扣掉 1 个对应输入，产物放得下才释放线程。
- **只有废料空间里的放射性物品数量达到或超过并行线程数时，才会开新的一批线程**；
  存量不足时整台储罐不启动，补满到线程数后自动开始。燃料棒也计入这个数量（虽然不参与衰变）。
- **产物缓存满了以后，所有线程暂停**（也不会再开新的一批），
  用输出端口把产物抽走就会自动继续。
- 燃料棒不参与衰变，只在废料空间里存储。
- **运行音效**：只要有线程在跑，就以 2–9 tick 的随机间隔播放盖革计数器咔嗒声，
  直接复用乏燃料冷却池的 `tile.machine.spent_fuel_pool_geiger`，听感与乏燃料池一致；
  线程全部结束后自动安静。

## 4. 端口模式

### 输入废料（`radioactive_waste_input`，默认）
- 只能把**放射性物品**送进废料空间，不能抽出任何东西。
- 支持的放射性物品：镅-241 粉、钚-239 粉、钋-210 粉、铀-233 粉、铀-235 粉，以及所有燃料棒。
- 空间满了以后插入会被拒绝（管道、漏斗、手持都塞不进去）。
- 手持放射性物品直接右键端口可以快速投入。

### 输出衰变产物（`decay_product_output`）
- 只能抽出**衰变完成产物缓存**里的物品，不能插入。
- 会主动往相邻物品容器推产物。
- **废料空间里的燃料棒也可以直接从输出端口抽出**（燃料棒只是暂存，不衰变）。
- 产物缓存和燃料棒以外的废料不会被输出端口抽出。

## 5. GUI

右键外壳或端口打开（结构成型后），标题「放射性废料存储罐」。
界面使用 Mekanism 标准机器面板（195 × 256，与压水堆 / 沸水堆 / 粒子加速器一致），
三块 Mekanism 内嵌屏幕 + 标准玩家背包：

- **左上屏幕**：待衰变物品，第一行是清单标题，第二行是「存量 / 容量」，
  下面按配方顺序列出五种配方输入，再列其它放射性物品，所有燃料棒合并成一行；
  超过 4 行时末行显示「…」。
- **右上屏幕**：衰变完成缓存的「存量 / 容量」、并行线程「运行中 / 上限」、
  五条配方里的最高衰变进度；产物缓存满时额外显示「缓存已满，衰变暂停」。
- **下方屏幕**：五条配方各一行，显示「输入 → 产物  运行中 45%（×3）/ 已暂停 45% / 未运行」。

## 6. 实现位置

| 文件 | 内容 |
|---|---|
| `wastestorage/MeknucWasteStorageMultiblock.java` | 多方块管理器（名字 `wasteStorage`） |
| `wastestorage/MeknucWasteStorageValidator.java` | 成型校验：1–3 × 1–18 × 1–3，外壳/端口 + 内部空气 |
| `wastestorage/MeknucWasteStorageMultiblockData.java` | 两块存储空间、容量、衰变逻辑、端口槽位视图、自动输出 |
| `wastestorage/MeknucWasteStorageRecipes.java` | 五条衰变配方 |
| `wastestorage/MeknucWasteStorageCache.java` | 多方块缓存（槽位 + 并行线程列表，兼容旧版进度标签） |
| `wastestorage/MeknucWasteStorageContainer*.java` | 容器与菜单类型 |
| `wastestorage/tile/TileEntityWasteStorageCasing.java` | 外壳方块实体（主方块） |
| `wastestorage/tile/TileEntityWasteStoragePort.java` | 端口方块实体（模式切换 / 手持投入） |
| `client/gui/MeknucWasteStorageGui.java` | GUI |

数据同步：128 个存储槽通过容器同步（不绘制），并行线程的代表进度、线程数与
「产物已满」状态通过 `@ContainerSync` 同步，因此拆解重组、存档重载后进度都不会丢。
多方块缓存保存的是完整的线程列表（配方 + 进度），旧存档的 `decay_progress`
会自动转换成线程读取。
